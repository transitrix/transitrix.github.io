Installieren & starten

Zwei Schritte bis zum gerenderten Diagramm: Studio installieren, dann Ihre erste Datei erstellen.

1. Studio installieren

Wählen Sie Ihre Anwendung. VS-Code-kompatible Editoren verwenden die Open-VSX-Erweiterung; JetBrains und Obsidian haben eigene Plugins.

Cursor / VSCodium / Windsurf JetBrains-IDEs Obsidian Desktop

In Cursor, VSCodium und Windsurf genügt auch die Suche nach Transitrix Studio im Erweiterungen-Panel — sie lesen Open VSX.

Im regulären VS Code nehmen Sie stattdessen die Datei. Der Build von Microsoft liest ausschließlich den eigenen Marketplace, daher findet die Erweiterungssuche Studio dort nicht. Laden Sie die .vsix von der Open-VSX-Seite herunter und wählen Sie dann Erweiterungen → … → Aus VSIX installieren… oder führen Sie code --install-extension transitrix-studio-*.vsix aus. Gleicher Build, gleiche Version.

Sequenz-, Zustands- und ER-/Klassendiagramme rendern nativ über PlantUML — keine zusätzliche Erweiterung nötig. Für leichtere, schnellere Ansichten installieren Sie zusätzlich Markdown Preview Mermaid Support — dasselbe reine Textmodell, kein Lock-in.

Obsidian Desktop — manuelle Installation

Transitrix Studio 0.1.0 zeigt eigenständiges Diagramm-YAML in Ihren Notizen an. Voraussetzung: Obsidian Desktop 1.0.0 oder neuer.

  1. Laden Sie main.js, manifest.json und styles.css aus den Assets von Release 0.1.0 herunter.
  2. Erstellen Sie in Ihrem Vault den Ordner .obsidian/plugins/transitrix-studio/ und legen Sie alle drei Dateien direkt darin ab.
  3. Starten Sie Obsidian neu. Deaktivieren Sie unter Einstellungen → Community-Plugins den eingeschränkten Modus (Restricted mode), um Plugins zuzulassen, und aktivieren Sie Transitrix Studio.
  4. Kopieren Sie einen Codeblock aus den Beispielnotizen in eine Notiz und öffnen Sie diese in der Leseansicht (Reading view).

Unterstützte Blöcke: Goals, DGCA, DGA, Action network, Action Card, Blocks und Process Blueprint. Blocknamen und Einstellungen. Live Preview und Mobilgeräte werden nicht unterstützt. Jeder Block muss seine Diagrammdaten selbst enthalten: Dokumente mit ausschließlich view_config sowie sources-Verweise werden abgelehnt. Das Plugin verändert keine Notizen.

2. Im Code-Editor: Repository anlegen — oder nur eine erste Datei

Fügen Sie dies in einen beliebigen Coding-Assistenten ein — Claude Code, Cursor, Copilot Chat, Gemini CLI — im Ordner, in dem Sie arbeiten möchten:

Fetch and follow
https://raw.githubusercontent.com/transitrix/methodology/main/transitrix/skills/onboard/SKILL.md
— for any templates/<file> path it references (incl. ${CLAUDE_SKILL_DIR}/templates/<file>),
fetch it instead from
https://raw.githubusercontent.com/transitrix/methodology/main/transitrix/skills/onboard/templates/<file>

Der Assistent fragt, was Sie modellieren möchten, und legt es entsprechend an:

  • Leerer Ordner — das Transitrix-Repository Ihrer Organisation, von Grund auf: die Zonen canon/, field/, codex/, das transitrix.yaml-Manifest, AGENTS.md-Rollenanleitungen und ein GitHub-Actions-CI-Workflow, der jeden Pull Request validiert.
  • Bestehendes Repository — orientiert sich dort und fügt eine erste Datei hinzu.

In beiden Fällen: Öffnen Sie das Ergebnis in Ihrem Editor — das Diagramm rendert beim Tippen. Skill-Quelle →

Nutzen Sie den Claude-Code-Plugin-Workflow?

Gleiches Ergebnis, über die Terminal-claude-CLI:

/plugin marketplace add transitrix/methodology
/plugin install transitrix@transitrix-methodology
/transitrix:onboard

Kein Coding-Assistent zur Hand? Klonen Sie das Beispiel-Repository und öffnen Sie eine beliebige .transitrix.yaml-Datei unter canon/ — sehen Sie es gerendert, bevor Sie selbst schreiben.

Einem bestehenden Repository Ihres Teams beitreten

Jemand hat das Modell bereits aufgesetzt — klonen Sie es und tragen Sie bei wie bei jeder anderen Änderung:

  1. Repository klonen, im Editor öffnen (Viewer installiert — siehe oben).
  2. AGENTS.md im Stammverzeichnis lesen — Zonen, Notationen, Konventionen.
  3. Datei bearbeiten oder hinzufügen, dann npx @transitrix/cli validate <datei>.
  4. Pull Request öffnen — die CI validiert automatisch erneut.
