Transitrix Studio

Open your text model and see it as a diagram or report.

Transitrix Studio is a set of editor extensions and a command-line tool for models written with the Transitrix Methodology.

What you can open

Use the model examples to see how a capability map, process blueprint or BPMN process is written. Studio works with structured model files, including YAML with a notation-specific filename suffix.

In the VS Code extension, the Traceability Matrix and Requirements by Release reports use requirement and related records in the model. Review the report inputs and scope before choosing a report.

  • Strategy and processes: goal trees, DGCA/DGA chains, activity networks/cards, process maps and blueprints. VS Code adds Gantt, critical-path views and completion percentages when progress records exist. Notation guide and format overview. The CLI compiles YAML to BPMN 2.0 XML with automatic layout: BPMN quick start.
  • Capabilities and catalogues: applications, products, nested blocks and supported inline scenarios; catalogue previews depend on document form. VS Code reads capability maturity from dated history as of the current date. Capability history.
  • Report navigation: Requirements reports provide upstream/downstream navigation, element focus, adjacent-column comparison and scope counts with drill-down lists. They share product, project, release and date selection, retain context and refresh after model changes.
  • Compliance and verification: VS Code offers impact/coverage views, a gap dashboard and a requirement–verification matrix for requirements, assertions and verification results. These need corresponding model records. Compliance validation.
  • Numerical risk degrees: author likelihood, impact and residual risk on an explicit adopter-defined scale in Methodology 7.0.0 models and check them with the CLI; qualitative values remain supported. Numeric risk authoring.
  • Exports: VS Code saves supported previews as SVG/PNG, gap and requirement–verification reports as CSV, and Traceability Matrix/Requirements by Release snapshots as JSON. PNG clipboard copying is Windows-only. CLI compliance exports are Markdown/PDF; PDF requires optional WeasyPrint. Preview exports · CLI commands.
  • Scaffolding: VS Code commands and the CLI create goals, drivers, constraints and requirements with admission/lifecycle fields, checking IDs and references before writing. Element creation.
  • CI validation: the CLI validates files or repositories and emits JSON findings with file-coverage counts. Unsupported forms are reported as unvalidated and fail strict repository validation. The model's methodology version selects ACTION numeric rules. CLI reference · Validation scope.

Technical sequence, state, ER/class and C4 views use PlantUML, a foreign format previewed natively in Studio without Java or Graphviz, including vscode.dev. Lighter views can use Mermaid through the recommended editor extension. Models stay plain, diffable text, readable without our tooling.

Studio is the public reference implementation of the methodology. See Semantic Standards and Interoperability for ArchiMate 3.2/BPMN 2.0 foundations and maintained differences.

Choose an editor or the command line

VS Code-compatible editors · 3.10.0
Preview supported diagrams, including BPMN, and use repository reports. Cursor, VSCodium and Windsurf can install from Open VSX. For Microsoft VS Code, use the VSIX file. Recognised previews open automatically and refresh on save; autosave shortens the loop. Preview settings.
JetBrains IDEs · 3.10.0
Compatible IDE builds 242–262 with JCEF show a read-only snapshot for strategy, process-map/blueprint and supported catalogue notations. Open Transitrix: Preview Notation from the editor context menu; reopen after edits. BPMN, requirements/compliance reports and SVG/PNG export commands require VS Code. Standalone JetBrains previews cannot resolve capability history; use VS Code or repository validation. Installation · Marketplace listing.
Obsidian Desktop · 0.1.1
The separate plugin previews supported, self-contained YAML blocks in Reading view. It requires Obsidian Desktop 1.0.0 or newer.
Command-line tool · 2.13.0
Install separately to validate supported model files or compile BPMN YAML to BPMN XML. The CLI requires Node.js 20 or newer.

Editor plugins bundle renderers, not a shell command. Install the CLI separately. No DSM installation is required.
